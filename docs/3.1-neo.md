# 3.1 Neo Implementation Notes

## Goal

3.1 Neo implements the 4.0-class platform direction under a 3.x release name. Prediction Market is the only intentionally optional feature and is disabled by default.

## New boundaries

- `mesh.py` — federated Knowledge Mesh
- `teams.py` — Agent team planning
- `router.py` — Skill routing
- `governance_os.py` — explainable decision ledger
- `resources.py` — resource budgets
- `privacy_mesh.py` — finite privacy budgets
- `skill_lineage.py` — fork/composition lineage
- `agents_os.py` — machine-friendly Agent facade
- `benchmark_network.py` — federated benchmark records
- `plugin.py` — plugin boundary
- `prediction.py` — optional forecast ledger

Legacy modules remain as compatibility facades.

## Personal vs federated

`deployment_mode=personal` keeps all data local and federation optional.

`deployment_mode=federated` enables node identity, federation policy, signed artifacts, and Knowledge Mesh exchange.

No data is automatically published to federation merely because the node is federated.

## Trust

Trust is layered:

```text
identity → capability → reputation evidence → node policy → authorization
```

A portable credential is not an admin credential. Federation trust is not Agent trust.

## Collective intelligence

Knowledge imported from another node is visible according to artifact visibility and local policy. High-value decisions can be explained via the Decision Ledger with evidence and policy references.

## Security model

3.1 adds additional defensive checks but still treats the external Agent runtime as untrusted. Real OS isolation should be provided by a sandbox runtime, container or VM.
